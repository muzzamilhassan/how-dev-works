# Diagram Lab — code → diagram starter kit

Hands-on examples of the four core "diagram as code" tools, themed for the
DB/SQL-internals channel concept (see docs/research/2026-10-04-diagram-channel-automation-research.md).
Render everything with one click: **Actions tab → "diagram-lab" → Run workflow**,
then download the `diagrams` artifact. Nothing here touches the live pipeline
(workflow is manual-trigger only, files are inert).

## The mental model

You write plain text → the engine lays out and renders an SVG/PNG. No dragging.
The text lives in git, diffs like code, and regenerates the diagram forever.

## The 4 tools and when to use which

| Tool | File here | Best for | Render time (CI) |
|---|---|---|---|
| **Mermaid** (`.mmd`) | `mermaid/01-insert-flow.mmd` | flowcharts, sequences — fastest to write, LLMs know it best, renders in GitHub markdown | ~2–5 s |
| **D2** (`.d2`) | `d2/01-insert-storyboard.d2` | most beautiful architecture diagrams; `steps:` boards = a storyboard (each step inherits the previous) | <1 s |
| **Python Diagrams** (`.py`) | `diagrams_py/01-replication.py` | cloud/on-prem architecture with real vendor icons (AWS/Azure/GCP/K8s) | ~2 s |
| **PlantUML** (`.puml`) | `plantuml/01-insert-sequence.puml` | deep UML: sequence/class/state | ~2 s |

## Three ways to use them

1. **Right now, zero setup (browser):**
   - Mermaid → https://mermaid.live — paste `mermaid/01-insert-flow.mmd`
   - D2 → https://play.d2lang.com — paste `d2/01-insert-storyboard.d2`
   - PlantUML → https://www.plantuml.com/plantuml — paste the `.puml`
   - Python Diagrams → the official online playground (linked from https://diagrams.mingrammer.com)
2. **Local CLI:** see the exact commands in `.github/workflows/diagram-lab.yml` —
   same commands run anywhere (`mmdc`, `d2`, `plantuml`, `python`).
3. **Automated (the pipeline way):** the `diagram-lab` workflow renders all four
   on a GitHub-hosted runner and uploads SVGs as an artifact. This is the seed of
   the channel pipeline: script → LLM emits diagram code → CI validates (exit
   code = syntax oracle) → SVG → Remotion progressive reveal keyed to edge-tts
   word timestamps.

## Feeding these into Remotion (the animation step)

- **Mermaid SVG:** mmdc output has stable, addressable ids per node/edge
  (`#flowchart-A-0`, `#L_A_B_0`, `.edgePath`) — inject with
  `dangerouslySetInnerHTML`, then reveal node-by-node as a function of
  `useCurrentFrame()` (opacity/spring per id, stroke-dashoffset for edges).
- **D2 storyboard:** render with `--animate-interval 700` → ONE animated SVG
  stepping through boards; or render the plain SVG (one file per board) and map
  each board to a Remotion `<Sequence>` — the board IS the reveal order.
- **Pin versions** (mermaid-cli especially) so ids stay stable across renders.

## Notes

- AWS/Azure/GCP icons (used by Python Diagrams) are explicitly permitted in
  monetized explainer videos — keep them unmodified, never recolor
  (source: vendor icon usage guidelines, cited in the research report).
- ChartDB / DrawDB (ER tools from the survey) are browser-only — great for
  manual schema exploration, NOT CI-automatable; use DBML or Mermaid `erDiagram`
  when an ER diagram must be generated by the pipeline.
